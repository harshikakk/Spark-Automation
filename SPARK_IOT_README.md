# SPARK Drives & Automation — Industrial IoT Control Center

This project adapts the uploaded Adminator 2026 vanilla-JS dashboard into a Spark Drives & Automation Industrial IoT control center.

## Important: uploaded template

The uploaded archive is **Adminator 4.3.0**, not CoreUI. The existing Adminator shell, token system, SCSS, responsive layout and Chart.js stack have been preserved and repurposed rather than replacing the project with a new dashboard.

## Firebase

Firebase configuration is centralized in:

`src/assets/scripts/2026/firebase.js`

The provided Firebase project configuration has been inserted there.

The current device model is intentionally simple:

```text
devices/
  ESP32-LED-001/
    name: "ESP32 LED Controller"
    ledState: 0
    status: "offline"
    lastSeen: null

history/
  event-id/
    deviceId
    state
    previousState
    source
    eventType
    timestamp
```

`ledState` is the single control value:

- `0` = OFF
- `1` = ON

The website listens to this value in realtime and writes it when the user operates the LED control.

### Test data

Use `firebase-test-data.json` in Firebase Console → Realtime Database → Data.

### Development rules

Use `firebase-rules.json` while developing with your Firebase Authentication users.

These rules require an authenticated Firebase user for database read/write access. Tighten them before production deployment if you add multiple user roles/devices.

## Test the website before ESP32

1. Create/confirm a user in Firebase Authentication.
2. Import the test data.
3. Publish the development rules.
4. Run the project.
5. Sign in with your Firebase Authentication user.
6. In Realtime Database, change:
   `devices/ESP32-LED-001/ledState`
   from `0` to `1`.
7. The website should update to ON without a page refresh.
8. Change it back to `0`; the website should update to OFF.

This verifies the website ↔ Firebase realtime path before the ESP32 is connected.

## ESP32 integration later

The intended simple device flow is:

```text
Website
   ↕
Firebase Realtime Database
   ↕
ESP32
   ↓
Physical LED
```

The ESP32 should read `devices/ESP32-LED-001/ledState` and set its GPIO accordingly. It should also write device telemetry such as `status` and `lastSeen`.

When the HMI is connected later, it can use the same Firebase/ESP32 path so the website sees the change through the realtime listener.

## Notes

- The website does not fabricate device status, LED state or history.
- Missing Firebase/device values are displayed as `Data unavailable`.
- History entries generated by the website use source `Website`.
- HMI/ESP32 firmware can later write history entries with their own source.
- The Excel export uses the actual currently filtered Firebase history.
